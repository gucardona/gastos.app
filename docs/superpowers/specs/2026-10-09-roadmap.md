# gastos.app — Roadmap de reescrita

**Data:** 2026-10-09
**Status:** Draft — aguardando revisão

## Contexto

O app ainda não tem usuários (nem o próprio autor usa em produção). Isso libera tudo:
schema, API, estrutura de pastas e frontend podem mudar sem compatibilidade retroativa.
O banco atual pode ser descartado.

Problemas que motivam a reescrita (levantados na revisão de 2026-10-09):

- Migrations acumuladas (~950 linhas em `src/db/db.go`) para um banco sem dados reais.
- `PRAGMA foreign_keys` aplicado em só uma conexão do pool → cascades inconsistentes.
- Materialização de recorrências dentro de GETs, com corrida que pode duplicar lançamentos.
- PATCH de entradas/recorrências/metas reatribui `user_id` para quem editou.
- Dinheiro em `REAL`; splits em percentual float.
- Roteamento manual (parse de path + `switch r.Method`) em todos os handlers.
- Frontend em um único `index.html` de 165 KB (Alpine + Chart.js via CDN).
- Deploy compila na VDI; binário commitado no repo; sem CI.

## Decisões transversais

- **Dinheiro sempre em centavos (`INTEGER`)** no banco, na API e no frontend. Formatação só na borda (UI).
- **Splits em basis points** (`10000` = 100%), soma exata, sem float.
- **"Carteira" vira `wallet`** no código e na API, para não colidir com "conta bancária" (`bank_account`) do Open Finance.
- **Gastos e entradas viram uma tabela só (`transactions`)** com `kind IN ('expense','income')`. Simplifica dashboard, recorrência e importação bancária, que já chega com sinal.
- **Sessão por cookie httpOnly** (token opaco em tabela `sessions`) no lugar de JWT em localStorage. O frontend é servido na mesma origem; SSE passa a autenticar pelo cookie, sem token na query string.
- **Frontend embutido no binário** (`go:embed`). Deploy continua sendo um único arquivo.
- **Um binário, um SQLite, um systemd unit.** Sem Docker por enquanto — não há ganho para um app pessoal em uma VDI.
