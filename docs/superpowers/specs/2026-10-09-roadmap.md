# gastos.app — Rewrite roadmap

**Date:** 2026-10-09
**Status:** Draft — awaiting review

## Context

The app has no users yet (not even the author uses it in production). That frees everything:
schema, API, folder structure and frontend can change without backward compatibility.
The current database can be discarded.

Problems that motivate the rewrite (raised in the 2026-10-09 review):

- Accumulated migrations (~950 lines in `src/db/db.go`) for a database with no real data.
- `PRAGMA foreign_keys` applied on only one connection of the pool → inconsistent cascades.
- Recurrence materialization inside GETs, with a race that can duplicate transactions.
- PATCH of incomes/recurrences/goals reassigns `user_id` to whoever edited.
- Money in `REAL`; splits as a float percentage.
- Manual routing (path parsing + `switch r.Method`) in every handler.
- Frontend in a single 165 KB `index.html` (Alpine + Chart.js via CDN).
- Deploy builds on the VDI; binary committed to the repo; no CI.

## Cross-cutting decisions

- **Money always in cents (`INTEGER`)** in the database, the API and the frontend. Formatting only at the edge (UI).
- **Splits in basis points** (`10000` = 100%), exact sum, no float.
- **"Carteira" becomes `wallet`** in the code and the API, so it does not collide with the Open Finance "bank account" (`bank_account`).
- **Expenses and incomes become a single table (`transactions`)** with `kind IN ('expense','income')`. This simplifies the dashboard, recurrence and bank import, which already arrives signed.
- **httpOnly cookie session** (opaque token in a `sessions` table) instead of a JWT in localStorage. The frontend is served from the same origin; SSE authenticates through the cookie, with no token in the query string.
- **Frontend embedded in the binary** (`go:embed`). Deploy stays a single file.
- **One binary, one SQLite, one systemd unit.** No Docker for now — no gain for a personal app on a VDI.
